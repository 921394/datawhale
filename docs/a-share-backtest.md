# A 股本地回测流程

目标不是马上赚钱，而是完成一条可检查、可重复的研究链路：

```text
合规取得的行情文件
    -> 清洗与检查
    -> 计算信号
    -> 模拟成交
    -> 统计绩效
    -> 样本外验证
    -> 生成报告
```

当前阶段不连接真实账户，不使用真实 API 密钥。

## 1. 先确认 A 股规则

回测前至少要明确：

- 交易时段和集合竞价；
- 买入数量和最小价格变动单位；
- 买入后何时可以卖出；
- 停牌、涨跌幅、除权除息和分红如何处理；
- 手续费、印花税、过户费和最低收费；
- 股票池是否包含退市股票，是否存在幸存者偏差。

规则以交易所和券商的最新公告为准。上交所交易规则包含交易时段、100 股申报单位和回转交易等规定：[上海证券交易所交易规则](https://www.sse.com.cn/lawandrules/sselawsrules2025/stocks/exchange/c/c_20260424_10816482.shtml)。

## 2. 准备最小环境

只需要 Python 和几个常用库：

```bash
python -m venv .venv
source .venv/bin/activate
pip install pandas numpy matplotlib jupyter
```

Windows 激活虚拟环境的命令不同，遇到问题直接把完整报错交给 AI。

数据可以先使用一份 CSV。不要为了“实时”一开始接很多数据源，先确保数据来源合规、字段含义清楚、时间范围固定。

建议的最小字段：

```text
date, symbol, open, high, low, close, volume
```

如果使用复权价格，必须在 README 中写明复权方式；如果策略涉及成交价格，不能把未来才知道的收盘价提前用于当天成交。

## 3. 检查数据

在计算任何指标前，先检查：

- 时间列能否解析，时区是否统一；
- 数据是否按 `symbol, date` 排序；
- 是否存在重复时间戳；
- OHLC 是否满足 `high >= max(open, close, low)` 等基本关系；
- 是否存在缺失值、零成交量或异常价格；
- 股票代码是否在整个回测期间都可见；
- 复权、分红、拆股和停牌是否有明确处理方式。

这一阶段的交付物是一份数据质量报告，而不是收益曲线。

## 4. 写一个最简单的策略

先选一个容易解释的规则，例如双均线或定期再平衡。策略说明必须回答：

1. 什么时候产生信号？
2. 信号使用的是哪一个时点的数据？
3. 订单在什么时候提交和成交？
4. 买多少，卖多少，是否允许加仓？
5. 什么条件下退出？
6. 现金不足、停牌或无法成交时怎么办？

不要先使用机器学习、自动选股或几十个技术指标。先让别人只看文字就能复述策略。

## 5. 做诚实的模拟成交

回测至少要有：

- 手续费、印花税、过户费等费用参数；
- 滑点或成交价偏移参数；
- 现金余额和持仓数量；
- 交易单位和资金不足检查；
- 停牌、涨跌幅限制和无法成交的处理；
- 每笔订单、成交、费用和剩余持仓记录；
- 每日组合净值。

回测引擎可以先自己用 pandas 写一个很小的版本，也可以使用 VectorBT。关键不是框架名称，而是明确撮合假设并把假设写进报告。

## 6. 输出结果

至少输出以下内容：

- 总收益和年化收益；
- 最大回撤及发生时间；
- 波动率；
- 交易次数和换手率；
- 胜率、平均盈利、平均亏损和盈亏比；
- 买入并持有基准；
- 净值曲线和回撤曲线；
- 完整交易明细。

不要只看总收益。一个收益更高但回撤巨大、换手很高或只靠少数几笔交易的策略，未必更可靠。

## 7. 防止回测造假

至少做以下验证：

- 按时间切分训练区间和样本外区间，不能随机打乱时间序列；
- 只使用当时已经可以获得的数据；
- 检查是否把当天收盘价用于当天收盘前成交；
- 检查股票池是否提前知道未来的上市、退市和成分变更；
- 用不同手续费、滑点和参数重新运行；
- 做走步或滚动验证；
- 与简单基准比较；
- 保存每次运行的配置和结果，避免只保留最好的一次。

## 8. 第一个项目的验收标准

完成下面清单，才算本地回测闭环完成：

- [ ] 一个明确的标的范围和时间范围；
- [ ] 一个简单、可解释的策略规则；
- [ ] 数据质量检查脚本或报告；
- [ ] 手续费、滑点和资金约束；
- [ ] 交易明细和每日净值；
- [ ] 绩效指标和基准对比；
- [ ] 样本外结果；
- [ ] 一条可以重新运行的命令；
- [ ] README 写清数据来源、假设和已知限制。

## 9. 下一步才是券商接口

本地回测稳定后，再研究券商仿真和量化接口。A 股实盘接口取决于券商、账户和权限，不能假定安装一个 Python 包就能交易。程序化交易还涉及报告、监控和风控要求，实盘前应向券商确认。[证监会证券市场程序化交易管理规定](https://www.csrc.gov.cn/csrc/c100028/c7480577/content.shtml)

顺序保持为：

```text
本地回测 -> 仿真交易 -> 人工复核 -> 小额实盘
```
