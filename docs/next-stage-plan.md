# 从文档到可运行项目

目前已经有了框架调查、A 股回测流程、AI 使用方法和完整工作流。下一步缺的不是更多框架，而是一个**可以运行、可以测试、可以复现的最小项目**。

## 1. 还缺哪些环节

### 项目骨架

把学习文档变成可执行项目：

```text
data/
src/
tests/
notebooks/
configs/
README.md
pyproject.toml
```

至少包含：

- 一份 10～100 行的示例行情数据；
- 一个数据检查脚本；
- 一个双均线策略；
- 一个回测入口；
- 一个绩效报告；
- 几个最小测试。

### 数据层

目前需要把“数据检查”真正实现出来：

- CSV 读取和字段校验；
- 日期、股票代码和排序标准化；
- 缺失值、重复数据和异常价格检查；
- 复权处理；
- 停牌和异常成交处理；
- 股票池历史快照；
- 数据质量报告。

### A 股成交模拟

需要将规则写成代码和测试，而不是只写在文档里：

- 买入后不能立即卖出；
- 100 股交易单位；
- 涨跌停时无法按普通价格成交；
- 停牌时无法成交；
- 开盘成交和收盘成交的时点；
- 现金、持仓和订单状态的一致性。

### 策略验证

回测报告还需要增加：

- 买入并持有基准；
- 样本内和样本外切分；
- 参数敏感性；
- 走步验证；
- 手续费和滑点压力测试；
- 不同市场阶段的表现比较。

### 仿真和实盘

本地回测之后，还需要验证：

```text
实时行情 -> 信号 -> 模拟订单 -> 模拟成交 -> 持仓同步
```

重点观察重复下单、部分成交、撤单失败、网络断线、程序重启，以及账户持仓与本地持仓不一致。

## 2. 当前最小可运行项目

第一版不要做多品种、机器学习或复杂界面，只完成：

```text
示例 CSV
    -> 数据检查脚本
    -> 双均线策略
    -> 回测脚本
    -> 绩效指标
    -> 买入并持有基准
    -> A 股成交规则测试
```

验收清单：

- [ ] 能用一条命令重新运行；
- [ ] 数据质量检查有明确输出；
- [ ] 策略信号没有使用未来数据；
- [ ] 包含手续费、滑点和资金约束；
- [ ] 输出交易明细和每日净值；
- [ ] 输出总收益、最大回撤、换手率和基准对比；
- [ ] 有人工构造数据的单元测试；
- [ ] README 写清数据来源、假设和已知限制。

## 3. 入门阶段

入门阶段只做：

```text
单个股票或 ETF
+ 日线数据
+ 一个简单规则
+ pandas
+ 本地回测
+ 买入并持有基准
```

建议练习双均线、定期再平衡、简单动量和简单均值回归。目标不是赚钱，而是弄清楚：

- 数据是什么；
- 信号何时产生；
- 订单何时成交；
- 持仓如何变化；
- 费用如何影响收益；
- 为什么回测结果可能不可信。

## 4. 中级阶段

完成第一个回测后，再逐项增加：

1. 多股票股票池；
2. 横截面排名；
3. 组合权重；
4. 调仓周期；
5. 行业和单股限仓；
6. 更真实的滑点；
7. 样本外和走步验证；
8. 因子研究；
9. 仿真交易。

这时可以使用：

```text
pandas + VectorBT
    -> Qlib 做因子研究
    -> vn.py 或券商接口做仿真
```

不要同时学习多个回测框架，先把一个项目做完。

## 5. 进阶阶段

以下属于进阶内容，不应作为第一个项目：

- 分钟级或 Tick 级策略；
- 盘口和订单簿；
- 事件驱动撮合引擎；
- 多因子组合；
- 机器学习选股；
- 深度学习和强化学习；
- 自动参数搜索；
- 多账户、多策略统一执行；
- 分布式回测；
- 生产级监控、容灾和回滚。

## 6. 从现成策略到自研策略

现成策略不是交易答案，而是教学样例。推荐按下面顺序使用：

```text
原样运行
    -> 看懂指标和信号
    -> 检查未来数据泄漏
    -> 加入 A 股交易规则
    -> 修改一个参数
    -> 修改一个规则
    -> 做样本外验证
    -> 提出自己的市场假设
    -> 自己设计策略
```

当你能够解释数据字段、信号时间、成交时间、手续费、滑点、最大回撤，并完成样本外验证后，就可以进入自研。

自研策略必须写完整：

```text
市场假设
    -> 可观测数据
    -> 指标或因子
    -> 买卖信号
    -> 仓位大小
    -> 交易执行
    -> 风险控制
    -> 回测与验证
```

“均线金叉买入”不算完整策略，因为还缺少成交、仓位、退出、交易成本和风险规则。

## 7. AI 的使用边界

AI 可以帮助解释概念、生成最小代码、分析报错、生成测试数据和审查未来数据泄漏。每次生成代码后，必须人工确认：

- 时间是否对齐；
- 成交时点是否正确；
- 手续费和滑点是否真正影响净值；
- 停牌和涨跌停是否错误成交；
- 程序重启后是否会重复下单；
- 密钥是否出现在代码、日志或 Git 历史。

代码能运行不等于回测正确。不要直接让 AI 生成“自动赚钱策略”或完整交易平台。

## 8. 推荐的实际顺序

```text
先完成最小项目
    -> 加入 A 股成交约束
    -> 增加多股票和组合管理
    -> 完成样本外验证
    -> 进入仿真交易
    -> 确认券商接口和合规要求
    -> 最后才考虑小额实盘
```
