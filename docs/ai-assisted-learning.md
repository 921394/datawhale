# AI 辅助学习与开发

AI 适合做解释、样例、重复代码、报错分析和代码审查。它不应该替你决定数据是否可信、回测假设是否合理，或是否可以把程序连接到真实账户。

## 通用提问模板

每次提问尽量提供：

```text
目标：我想完成什么
环境：操作系统、Python 版本、已安装的库
输入：文件格式、字段、几行真实样例
当前代码：最小可复现代码
错误：完整 traceback
限制：只允许使用哪些库、不能改变哪些行为
验收标准：什么结果才算正确
```

## 可以直接复制的提示词

### 解释概念

```text
我是量化交易初学者。请用一个具体的 A 股交易例子解释“最大回撤”，先讲直觉，再给出计算公式，最后用 5 天的虚拟净值手算一遍。不要跳过中间步骤。
```

```text
请解释 A 股回测中的复权、滑点、手续费、停牌和未来数据泄漏。每个概念都给出：定义、一个错误例子、一个正确处理方式。
```

### 生成最小数据代码

```text
我有一份 A 股 CSV，字段是 date,symbol,open,high,low,close,volume。
请只使用 pandas 写一个数据检查脚本，检查：日期解析、排序、重复时间戳、缺失值、OHLC 关系、异常成交量，并输出清晰的检查报告。
不要写交易策略，不要下载网络数据。
```

### 写第一个回测

```text
我是量化初学者，请用 Python 和 pandas 读取这份 A 股行情 CSV，写一个最简单的双均线回测。

要求：
1. 明确说明信号使用哪个时点的数据；
2. 不允许未来数据泄漏；
3. 包含手续费、滑点、现金余额和持仓数量；
4. 输出交易明细、每日净值、总收益、最大回撤和买入并持有基准；
5. 先生成 10 行人工测试数据，验证手续费、滑点和仓位变化；
6. 代码拆成小函数，并逐行解释关键逻辑；
7. 最后列出这段回测仍然没有模拟的 A 股规则。
```

### 审查未来数据泄漏

```text
请逐行审查下面这段 A 股回测代码，重点检查未来数据泄漏、收盘价提前成交、复权使用错误、股票池幸存者偏差和交易日错位。
对每个问题给出：代码位置、为什么是问题、一个最小反例、最小修改方案。
如果没有发现问题，也请说明你检查了哪些路径。
```

### 解释报错

```text
请解释下面的完整 Python traceback。先指出真正出错的那一行，再说明根因，给出最小修复，并告诉我如何验证修复没有改变其他逻辑。
环境：
Python版本：
已安装库版本：
完整代码：
完整报错：
```

### 做代码审查

```text
请以严格的代码审查方式检查这份量化代码，只关注会导致错误交易或错误回测的风险：
数据泄漏、重复下单、订单状态不同步、断线恢复、持仓对账、异常行情、密钥暴露、手续费遗漏。
按严重程度排序，每项给出证据和最小修复建议，不要进行无关重构。
```

## AI 生成代码后的人工检查

至少逐项确认：

- 输入和输出的数据类型是否正确；
- 时间列是否排序、是否有时区混用；
- 指标是否只使用当时可见的数据；
- 信号产生时间和订单成交时间是否区分；
- 手续费、滑点和交易单位是否真正影响净值；
- 无现金、停牌、涨跌幅限制时是否会错误成交；
- 订单失败或程序重启后是否会重复下单；
- API 密钥、PAT 和券商密码是否出现在代码、日志或 Git 历史中。

“代码能运行”只能证明语法和部分路径可用，不能证明回测逻辑正确。

## 推荐的 AI 协作方式

```text
先让 AI 解释问题
    -> 再让 AI 写最小版本
    -> 用人工构造数据测试
    -> 让 AI 审查边界条件
    -> 自己阅读并修改
    -> 再接真实历史数据
```

每次只解决一个小问题。不要一次要求 AI 生成完整交易平台；那样很容易得到能启动、但无法验证的复杂代码。
