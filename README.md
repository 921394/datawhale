# 开源量化交易平台调查

更新时间：2026-08-23

## 结论先行

没有一个框架在研究、回测、实盘接入和低延迟方面都最好。建议把研究层和执行层分开选：

- 国内期货/股票：`vn.py + VectorBT/Qlib`
- 全球多资产：`LEAN`
- 多交易所、强调回测与实盘一致性：`NautilusTrader`
- 加密货币趋势策略：`Freqtrade`
- 加密货币做市/套利：`Hummingbot`
- 机器学习因子研究：`Qlib`

## 框架对比

| 框架 | 适合场景 | 主要特点 | 适合作为完整平台 |
| --- | --- | --- | --- |
| [QuantConnect LEAN](https://github.com/QuantConnect/Lean) | 全球股票、期货、期权、外汇、加密货币 | C# 核心，支持 Python；事件驱动；本地回测和实盘；多资产 | 是 |
| [NautilusTrader](https://nautilustrader.io/docs/) | 多市场、多交易所、对延迟和回测一致性有要求 | Rust 原生核心，Python 写策略；回测和实盘共用事件模型 | 是 |
| [vn.py / VeighNa](https://www.vnpy.com/) | 中国期货、股票、期权、CTP | Python；国内 Gateway 较丰富；包含 CTA、套利和算法交易应用 | 是，国内市场优先 |
| [Microsoft Qlib](https://github.com/microsoft/qlib) | 因子研究、机器学习、组合优化 | 覆盖数据处理、因子、模型训练、回测、风险和组合流程 | 研究层为主 |
| [VectorBT](https://vectorbt.dev/) | 参数扫描、因子研究、快速回测 | 基于 NumPy、pandas、Numba/Rust，适合批量实验 | 否，研究层为主 |
| [Freqtrade](https://github.com/freqtrade/freqtrade) | 加密货币趋势策略 | Python；回测、Dry-run、实盘、Web UI、Telegram、参数优化 | 是，偏个人机器人 |
| [Hummingbot](https://github.com/hummingbot/hummingbot) | 加密货币做市、套利、CEX/DEX | 交易所连接器多，专注自动化做市和套利 | 是，偏加密执行 |
| [Backtrader](https://www.backtrader.com/docu/) | 学习、简单策略和传统回测 | Python；接口直观，指标和 Broker 支持丰富 | 不建议作为新平台核心 |
| [Zipline Reloaded](https://github.com/fstp/zipline-reloaded) | 股票研究和事件驱动回测 | Quantopian Zipline 的社区维护版本 | 研究层为主 |

## 推荐架构

```text
数据层：行情、复权、合约信息、交易日历
研究层：因子、特征、回测、组合优化
执行层：订单路由、成交回报、撤单、重连、持仓同步
风控层：限仓、限频、最大亏损、熔断、人工接管
```

推荐先完成一个最小闭环：

```text
历史回测 -> 仿真盘/Dry-run -> 小资金实盘
```

## 零基础快速上手

不需要先把所有数学、金融和工程知识学完。可以让 AI 解释定义、生成示例、阅读报错和补充代码；但每一步都要运行代码、检查结果，并保留可复现的输入和输出。

### 一张知识地图

| 层次 | 必须理解的内容 | 常用工具 | 最小交付物 |
| --- | --- | --- | --- |
| 市场基础 | 股票/期货/期权/加密货币的交易规则、合约乘数、保证金、交易时间、订单类型 | 交易所规则、券商文档 | 能解释一次买入、成交、手续费和持仓变化 |
| Python 与数据 | 变量、函数、模块、异常；表格、时间序列、缺失值、时区、排序 | Python、`pandas`、`numpy`、Jupyter | 读取一份行情文件，画出价格和收益曲线 |
| 收益与风险 | 收益率、波动率、最大回撤、夏普比率、换手率、胜率、盈亏比 | `pandas`、`matplotlib` | 对一个基准策略输出完整绩效表 |
| 策略表达 | 信号、持仓、仓位、调仓、止损、止盈、再平衡；把自然语言规则写成无歧义条件 | Python、流程图 | 一份别人可以复述的策略规则 |
| 回测 | 撮合、滑点、手续费、成交延迟、资金约束、复权、涨跌停和停牌 | VectorBT、Backtrader 或 LEAN | 可重复运行的回测脚本和结果报告 |
| 统计与研究 | 基准、训练/测试划分、样本外验证、显著性、相关性、因子、回归、过拟合 | `scipy`、`statsmodels`、Qlib | 一份包含样本外结果的研究报告 |
| 组合与资金管理 | 资产配置、仓位上限、集中度、杠杆、风险预算、再平衡 | Qlib、LEAN 或自定义 Python | 给定风险约束下的组合权重 |
| 执行 | 行情订阅、订单状态机、成交回报、撤单、重连、幂等、持仓对账 | vn.py、LEAN、NautilusTrader、Freqtrade | 仿真盘中订单状态与持仓始终一致 |
| 风控 | 单笔/单日亏损限制、限仓、限频、熔断、异常行情、人工停止 | 执行框架的风控模块 + 独立规则 | 触发风险条件时系统拒绝下单 |
| 工程与运维 | 配置管理、日志、监控、告警、密钥、备份、权限、部署和回滚 | Git、Docker、SQLite/PostgreSQL、Prometheus | 能发现断线、异常订单和进程退出 |

### 推荐的学习顺序

1. **先做数据，不做交易。** 用一份 CSV 或公开数据完成读取、清洗、排序、收益率计算和可视化。先学会发现缺失值、重复时间戳和未来数据。
2. **再做一个最简单的规则策略。** 例如双均线或定期再平衡。规则必须写成明确的入场、持有、退出和仓位条件，不要一开始使用机器学习。
3. **把回测做得诚实。** 加入手续费、滑点、成交时点和资金约束；与买入并持有基准比较；分别查看收益、回撤、换手和交易明细。
4. **验证策略而不是优化曲线。** 固定一段样本外数据，做滚动或走步验证，检查参数轻微变化时结果是否仍然成立。不要因为回测好看就不断调参数。
5. **再选一个实盘框架。** 国内市场优先 `vn.py`，全球多资产看 `LEAN`，追求 Rust 性能和回测/实盘一致性看 `NautilusTrader`，加密趋势策略看 `Freqtrade`。
6. **先仿真，再小额实盘。** 仿真期间重点观察断线重连、重复下单、部分成交、撤单失败、余额和持仓对账；确认这些问题后再考虑真实资金。

### 第一个最小项目

项目目标不是赚钱，而是打通研究闭环：

```text
行情文件 -> 清洗 -> 计算信号 -> 模拟成交 -> 统计绩效 -> 生成报告
```

项目至少包含：

- 一个明确的交易标的和时间范围；
- 一个简单、可解释的规则策略；
- 买入并持有基准；
- 手续费和滑点参数；
- 每笔交易记录和每日净值；
- 总收益、年化收益、最大回撤、波动率、换手率；
- 一段没有参与调参的样本外数据；
- README，说明数据来源、假设、运行命令和已知限制。

### 如何使用 AI 学习和开发

让 AI 做重复劳动，但不要把判断责任交出去：

- **解释概念：**“用一个具体交易例子解释最大回撤，并给出计算公式。”
- **生成最小代码：**“只用 pandas 读取这份 CSV，检查时区、重复时间戳和缺失值。”
- **审查回测：**“逐行检查这段代码是否使用了未来数据，指出证据。”
- **解释报错：**提供完整 traceback、Python 版本和最小复现代码，不要只贴一句错误标题。
- **生成测试数据：**先用人工构造的 10 行行情验证手续费、滑点和仓位变化，再接真实行情。
- **做代码审查：**要求 AI 列出数据泄漏、重复下单、断线恢复和权限暴露风险，并逐项复现。

每次让 AI 生成代码后，至少自己确认：输入输出类型、时间对齐、交易发生时点、费用是否计入、异常时是否停止下单。AI 可以写出能运行的错误回测，运行成功不等于逻辑正确。

### 暂时不要做的事

- 不要一开始搭微服务、消息队列、分布式回测或漂亮的交易面板。
- 不要一开始训练深度学习、强化学习或自动因子挖掘模型。
- 不要把单次高收益回测当作策略有效性的证明。
- 不要把 API 密钥、PAT 或券商密码写入代码、README、日志或 Git 历史。
- 不要在没有仿真、限仓和人工停止开关时连接真实账户。

## 选型说明

### 国内市场

优先看 `vn.py`。它对 CTP、期货、期权和国内交易场景的接入更直接。研究部分可以用 `VectorBT` 做快速实验，或用 `Qlib` 做因子和机器学习流程。

### 全球多资产

优先看 `LEAN`。它的事件驱动模型、资产类别覆盖和本地运行能力适合搭建通用平台。需要更强的性能、确定性模拟和研究到实盘一致性时，考虑 `NautilusTrader`。

### 加密货币

- 趋势、网格、量化择时：`Freqtrade`
- 做市、跨所套利、CEX/DEX：`Hummingbot`
- 需要更通用的多交易所生产引擎：`NautilusTrader`

## 需要提前确认的风险

1. 开源框架不代表行情数据免费。数据质量、复权、合约生命周期和交易日历往往是主要工作量。
2. 回测通过不代表实盘可靠。订单状态同步、断线恢复、重复下单保护和人工接管必须单独验证。
3. 商业化前检查许可证。不同项目的许可证不同，例如 Freqtrade 使用 GPL-3.0，不能默认按任意方式闭源分发。
4. 不要一开始同时部署多个框架。先选一个市场和一个策略，完成回测、仿真和小资金实盘闭环。
